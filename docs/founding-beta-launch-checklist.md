# BruA1 free founding beta — owner-authorized launch checklist
The owner approved a free test launch for friends. First 50 accounts free, review at 25. No charges, credit cards or automatic paid conversion. Do not enable the paid subscription or beat checkout flags.

## Before enabling public signups
1. Confirm the main-branch Music Network locked deployment and static storefront deployment pass. Verify the Worker health endpoint: databaseReady true, locked true, memberApiEnabled false, publicBetaEnabled false, billingEnabled false.
2. Provision the dedicated managed Turnstile widget (brua1.com only) and the TURNSTILE_SITE_KEY / TURNSTILE_SECRET_KEY bindings on brua1-music-network. The preparation workflow never overwrites existing secrets or opens enrollment. If the API token lacks Turnstile permissions, the owner uses the Cloudflare dashboard to create the widget and enters the two bindings directly. Do not share the secret in chat or commit it. Do not use test keys in production.
3. Owner must approve the beta privacy/retention/support notice, assign a human moderator with actual dashboard access, and verify recovery procedures. The beta uses access keys: users must save them privately; no email recovery. Only adults during the pilot.
4. Owner checks D1 database brua1-music-network (not brua1-orders-production). Read counts: SELECT COUNT(*) FROM network_founding_members; review reports privately: SELECT id,target_kind,target_id,reason,status,created_at FROM network_reports WHERE status='OPEN' ORDER BY created_at; never publish report contents. For a verified abusive account, a scoped update of network_members.status='SUSPENDED' by exact member ID blocks future access; revoke its sessions and hide offending content as appropriate after review. Document decisions, avoid unreviewed bulk actions, and provide support for appeals/privacy requests.
5. Before allowing real accounts, address the current locked bootstrap's intentional refusal to operate on nonempty databases: use separately reviewed additive migrations and backups. Do not run a destructive reset or reopen/overwrite deployment flags automatically.
6. After operational gates are met, set NETWORK_MEMBER_API_ENABLED=true and NETWORK_PUBLIC_BETA_ENABLED=true and NETWORK_BETA_MODERATION_READY=true in the community Worker settings only. Keep NETWORK_BILLING_ENABLED=false and all commerce gates false. Leave invitation enrollment disabled unless deliberately authorized. The owner may close new signup independently by setting NETWORK_PUBLIC_BETA_ENABLED=false while preserving sign-in and community access.
7. First real browser acceptance test: open https://brua1.com/music-network.html, verify real Turnstile, create one consenting founder account, save the key, opt into a profile, post in General chat, sign out and sign back in. Confirm the registered/listed counts and billing remains disabled. Test reporting and blocking with a second consenting founder. If a test fails, close new registration and fix before sharing publicly. Never count fake fixtures as members.
8. Share the public page only once the browser acceptance test succeeds. Review at 25 real registered accounts and again at 50; no automatic monetization.
